# SalesmanPro — Application Security Architecture & Credential Vault

> **Document Type:** Security Specification & Threat Model  
> **Security Level:** Confidential — Engineering & DevSecOps  
> **Standard:** AES-256-GCM Cryptographic Storage & Zero-Trust Secrets Management  

---

## 1. Threat Model & Security Objectives

In a multi-tenant commerce and AI platform like SalesmanPro, compromised API credentials could result in:
1. **Financial Fraud:** Hijacked payment webhooks or unauthorized payment captures.
2. **AI Quota Exhaustion:** Stolen inference keys utilized for unauthorized batch operations.
3. **Data Exfiltration:** Unauthorized read/write access to customer orders, customer PII, and WhatsApp messages.
4. **Tenant Impersonation:** Cross-tenant access to competitor store metrics or private credentials.

To eliminate these vulnerabilities, SalesmanPro implements a **defense-in-depth security model**:

```text
[ Incoming Request ]
        ↓
[ NextAuth Session + RBAC Check (requireSuperAdmin) ]
        ↓
[ Local Credential Vault / DB Storage ]
        ↓ (AES-256-GCM Encrypted at Rest)
[ Decrypted ONLY in Protected Server Runtime ]
        ↓
[ Multi-Layer Sanitizer (secretRedaction.ts) ]
        ↓ (Scrubbed of All Tokens & Passwords)
[ Safe Diagnostic Logging / Append-Only Audit Trail ]
```

## 2. Cryptographic Storage Standards

### A. AES-256-GCM with Authenticated Authentication Tags
All tenant credentials stored in the MongoDB database (`PaymentSettings`, `WhatsAppAccount`, `PlatformAIProvider`, `PlatformSocialAppConfig`, `EmailConfiguration`) are encrypted using **AES-256-GCM**:
- **Algorithm:** `aes-256-gcm`
- **Key Length:** 256 bits (32 bytes derived from `MASTER_ENCRYPTION_KEY` / `BACKUP_ENCRYPTION_KEY`)
- **Initialization Vector (IV):** 12 bytes cryptographically secure random bytes (`crypto.randomBytes(12)`) generated per operation. Never reused.
- **Authentication Tag (AuthTag):** 16 bytes authentication tag generated by the GCM cipher. Validates both confidentiality and ciphertext integrity against bit-flipping attacks.
- **Payload Schema in DB:**
  ```prisma
  accessTokenEncrypted  String?
  accessTokenIv         String?
  accessTokenTag        String?
  ```

### B. Master Key Security Invariants
- `MASTER_ENCRYPTION_KEY` must never be stored in the database.
- It resides exclusively in restricted file system environment variables (`.env` or `/var/www/salesmanpro/shared/.env`).
- **Rotation Rule:** Never rotate the master encryption key without running a coordinated migration script (`scripts/migrate-encryption-key.ts`) that decrypts all records with the old key and re-encrypts with the new key in a single atomic transaction.

## 3. Secret Redaction Engine (`secretRedaction.ts`)

SalesmanPro employs an automated redaction engine that intercepts all log output, error objects, and audit records before they reach terminal stdout, files, or API responses:

1. **High-Entropy Regex Filters:** Detects and scrubs known provider key formats:
   - OpenAI (`sk-[a-zA-Z0-9_-]{20,}`)
   - Groq (`gsk_[a-zA-Z0-9]{30,}`)
   - Google / Firebase (`AIza[0-9A-Za-z-_]{35}`)
   - Anthropic (`sk-ant-[a-zA-Z0-9-_]{30,}`)
   - Meta Graph (`EAAB[0-9A-Za-z]+`)
   - Stripe (`sk_live_...`, `sk_test_...`, `whsec_...`)
   - Paystack (`sk_live_...`, `sk_test_...`)
   - AWS Secret Access Keys (`[A-Za-z0-9/+=]{40}`)
2. **Connection String Passwords:** Automatically parses and removes embedded credentials from `mongodb://` and `redis://` URLs.
3. **HTTP Header Masking:** Masks `Authorization: Bearer <token>` in network logs.
4. **Key-Value Dictionary Scrubbing:** Automatically masks object properties matching `password`, `secret`, `token`, `key`, `passkey`, `credential`.

## 4. Local Credential Vault & Atomic Environment Updates (`credentialVault.ts`)

Manual editing of `.env` files is prone to syntax errors, accidental deletion of critical variables, and race conditions during worker restarts. The `CredentialVault` guarantees:

1. **Automated Timestamped Backups:** Before modifying `.env`, an immutable copy is created in `storage/backups/env/.env.backup.<ISO_TIMESTAMP>`.
2. **Comment and Structure Preservation:** Non-destructive parser retains all explanatory comments, empty lines, and original quote formats.
3. **Atomic Write Protocol:**
   - Changes are computed in memory.
   - Output is written to a temporary file `.env.tmp.<timestamp>`.
   - File is renamed atomically via `fs.renameSync` (POSIX atomic rename).
   - Prevents worker processes from reading half-written files.
4. **Duplicate Prevention:** Existing keys are updated in-place; new keys are cleanly appended at the end of the file under a tracked timestamp header.
5. **Masked Diffs:** API responses display whether a variable was `ADDED`, `UPDATED`, or `RETAINED` with masked values (`gsk_...[REDACTED]...abc`), never revealing the actual value.

## 5. Append-Only Audit Logging (`auditLogger.ts`)

Every credential modification, verification check, browser onboarding launch, and deployment staging event is permanently logged to `storage/audit/credential-onboarding-audit.jsonl`:

```json
{
  "id": "audit_1727880000000_abc123",
  "timestamp": "2026-10-02T17:41:30.000Z",
  "actor": "SUPER_ADMIN",
  "action": "CREDENTIAL_COMMITTED",
  "providerId": "ai-groq",
  "variableNames": ["GROQ_API_KEY", "GROQ_MODEL"],
  "status": "SUCCESS",
  "details": {
    "changesCount": 2,
    "backupPath": ".env.backup.2026-10-02T17-41-30"
  }
}
```

The audit trail is append-only, searchable in the Super Admin dashboard, and verified to contain zero plaintext secrets.
